1. **Exact rhythm and event identity (SYNC-01, RHY-01/02).** A tracker Cell has pitch/instrument/volume/effect, not string, fret, voice, written duration, spelling or tie identity. TuxGuitar has two voices per beat and exact timing for divisions through 13:8. Its legacy 960-tick quarter is not its precise authoring-time representation: TGDuration builds an LCM-based precise clock, including double dots. A fixed 48-rows-per-quarter score cannot preserve all of this. [N], [B], [V], [D], [DT]
2. **Playback projection cannot silently truncate.** Current gpimport.py caps channels at 64, a pattern at 200 rows and expanded orders at 255; grid_for falls back to 48 and warns when rounding. Those are import losses, not acceptable native-document semantics. Prove mixed tuplets/voices, ties across patterns, tempo/speed changes and simultaneous per-string bends before selecting a projection. Preserve score data even where a requested export cannot represent it.
3. **Effect ownership and meaning (SYNC-03, FX-*).** An imported Exx/Fxx/Gxx/Hxx sequence is not a reversible technique document. Deleting a bend must remove only its generated commands, preserving unrelated raw effects and automation. Upstream hammer playback reduces the next note's velocity; current GP import instead writes GFF legato. Palm mute and ghost handling also differ. A familiar symbol or existing importer is not evidence of TuxGuitar playback parity. [MP]
4. **Measures versus pattern occurrences (SYNC-04, BAR-03).** A displayed measure, a reusable pattern, and a played repeat pass are different identities. Retain repeat/endings structure, while edits to a shared pattern affect every use unless the user explicitly makes an occurrence independent. Existing arrangement mapping is useful but contains no score mapping. [MH], [MR]
5. **Tracks are not single tracker channels (TRK-01/04).** Upstream allows 1–25 strings, two voices, independent fingering, a track offset from -24 to +24 and a configurable maximum fret (default 29). Preserve stable logical tracks across channel allocation, sample/instrument changes, percussion and mixer edits. [TR]
6. **Two existing keyboard traditions (CMD-01).** Upstream defaults conflict with Pattern/OpenMPT: F5 is song properties, F7 settings, Space transport, Ctrl+A select all. TAB needs an explicit, visible context or configurable binding policy. Preserve Pattern's established behavior. A changed default must be named as a difference, not silently called exact shortcut parity. [KEYS]

## Transport, practice, sound and layout

Pinned transport source findings (2026-10-20; source evidence, not a runtime/audio verdict):

- The built-in `MidiSequencerImpl.setTickPosition/process/reset` sends all-notes-off and resets pitch bend on seek.
  `MidiEventPlayer.reset/shouldSend` chases earlier system/controller/program events, but not note-ons or pitch bends.
  `MidiSequenceParser.addBeat/getRealNoteDuration` extends the originating note for ties and omits tied continuation attacks. [SEQ], [EVPLAY], [MP]
- `MidiPlayer.finish/play/changeTickPosition/updateChannel` stops and rebuilds whole-song/configured measure-loop
  playback, reapplies channel parameters/program/controllers, and clamps the destination to the loop start.
  Selected beats instead select their containing measures and inhibit automatic replay. `MidiRepeatController.process`
  suppresses a written repeat-close on the configured loop's final measure. [PLAYER], [MR]
- `TGTransportModeAction.processAction` copies/reset percentages; `MidiSequenceParser.addTempo` bakes that percentage
  into the constructed sequence. This path supplies no immediate midbeat speed rescheduling; a rebuilt pass uses the
  changed value. Backend-specific release/reverb tails and Java Sound event chasing require runtime evidence. [MODEACTION], [MP]
- **Deliberate VultureTracker difference:** edit swaps and seeking reconstruct preceding score **and raw tracker**
  audio state, including sustained/tied voices, to retain existing tracker playback semantics. Loop wraps start a
  fresh reconstructed destination; they never carry outgoing voices from the previous pass. Replaying both streams
  restores instrument/controller memory and NNA/envelope state together. Existing immediate audition-speed behavior
  is also a difference; exact native speed rescheduling remains separate work.

Core replay check (2026-10-20): `engine-core.js` now retains a private copied native pair, maps order/row boundaries
with absolute BigInt half-up rounding, and exposes `fresh()` plus bounded forward-only `advanceTo()`. Fresh copies
preserve mute/channel-volume/pan overrides; direct native seek and non-unit speed still refuse. The existing
`tests/engine_check.js --score` JSON fields remain compatible. Candidate WASM passed the 13-tuplet fixture with
different render/replay block sizes. The existing Python memory/tie/NNA/Vxx fixture passed unchanged using
`--score backing.it plan.json --matching-replay`: bounded replay PCM exactly matched fresh reads with identical
partitions at event, occurrence, mid-tie and arrangement-end targets; input mutation, cancellation and overrides
passed. Its initial 127-versus-4096 block-independence check failed, consistent with the Python fixture's noted
